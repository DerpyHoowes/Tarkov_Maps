# Introduction
This little script for making interactive maps was generated by Claude AI (because all the existing tools for making interactive maps either lacked in functions or is locked behind a pay wall), I only made the prompts, so the README below is also generated, and I can't say how adequate it is.
Regardless, me and my friend fill out the maps on our own, by finding docs in raids or posts across media to compile them into proper maps.
To use the map, just download the script, press "Get from a link" in the top toolbar, and paste "https://github.com/DerpyHoowes/Tarkov_Maps/tree/main/maps", then press "Look Inside", select the desired map and press "Download and open".

# DerpMap

An interactive map maker: drop a high-resolution image in, pin the places that matter, describe
them, attach photos — and push the whole thing to a GitHub repository so other people can edit it
with you.

C# / .NET 10 / Avalonia 11.

---

## Build and run

```bash
dotnet run --project src/DerpMap/DerpMap.csproj
```

### Publishing

The app publishes as **Native AOT**: one native `DerpMap.exe` (~18 MB) next to the Skia, HarfBuzz
and ANGLE native libraries — no .NET runtime on the target machine, no JIT, and a cold start with
nothing to warm up.

```bash
dotnet publish src/DerpMap/DerpMap.csproj -c Release -r win-x64
```

or run `src/publish.bat`, which drops the result in `src/publish/win64`.

Publishing (not building) needs the **MSVC linker** on the machine doing the publish — Visual Studio
with *Desktop development with C++*, or the standalone Build Tools. Ordinary `dotnet build` and
`dotnet run` do not.

`win-arm64` is also configured; pass `-r win-arm64` and install the C++ ARM64 build tools.

#### Staying AOT-clean

AOT removes the reflection that a lot of convenient .NET APIs quietly depend on, and the failures
land at runtime in the shipped binary rather than at compile time. Two guards keep that from
happening:

* The trim, AOT and single-file **analyzers run on every ordinary build**, not just at publish, so a
  reflection-dependent API is a warning the moment it is written.
* `JsonSerializerIsReflectionEnabledByDefault` is **off**. Everything persisted goes through the
  source-generated context in [`Services/AppJson.cs`](src/DerpMap/Services/AppJson.cs); a type that
  is not declared there throws in Debug too, instead of only in the published app. Adding a new
  persisted root type means adding one `[JsonSerializable(typeof(T))]` line to it.

## What it does

### 1. High-resolution maps you can scroll

Any PNG / JPEG / BMP / GIF / WEBP becomes a map. The image is copied into the map's own folder, so
the original can be moved or deleted afterwards.

| Action | Input |
| --- | --- |
| Pan | Drag with the left button on empty map, or drag with the middle button anywhere |
| Zoom | Mouse wheel (zooms around the pointer) |
| Zoom in / out | `+` / `-` |
| Fit to window | `F`, or the **Fit** button |
| Nudge the view | Arrow keys |

The view is clamped so the map can never be panned off into the void.

### 2. Markers

Right-click the map → **Add marker here**, or press **＋ Add marker** and click where you want it.
**Lock** in the toolbar is on by default, because nudging a pin while panning is much easier to do
than to notice; switch it off when you want to drag markers around.

Each marker carries a name, a description, any number of photos, a category, a size multiplier, and
optional per-marker icon and colour overrides. Icons are either one of 24 built-in vector glyphs
(chest, skull, cave, camp, mountain, key, …) tinted with the category colour, or your own image file.

Markers keep a **constant on-screen size at any zoom level** — the icon counter-scales by `1 / zoom`
— so a map zoomed all the way out doesn't turn into a wall of giant pins.

* **Hover** a marker → a floating card with its name, category, description and a preview of the
  first attached photo.
* **Double-click** a marker → the full marker card: complete description, photo gallery with a
  thumbnail strip and captions, timestamps, and buttons to edit, show on map, or delete.

### 3. Legend

Down the left-hand side:

* **Categories** — each with a colour/icon swatch and a marker count. Untick one and every marker in
  it disappears from the map. **All** / **None** toggle everything at once.
* **Search** (`Ctrl+F`) — matches marker names, descriptions and category names as you type.
  Matching markers stay bright, everything else fades to 22% so you keep the spatial context.
  Click a result to centre the map on it; double-click to open its card.
  With an empty box the list doubles as a browsable index of every marker on the map.

* **Language** — a dropdown listing every language the map has, appearing as soon as there is more
  than one. It changes what you *read*, never what you edit.

**Manage categories…** opens the editor for adding, renaming, recolouring, reordering and deleting
categories. Deleting one that still holds markers asks whether to move them or delete them too.

### 4. Translations

A map is authored in English; **Translations…** (toolbar, or the button on the legend) adds any
number of other languages to it.

Adding a language starts it as a **copy of the English text**, so translating is editing lines
rather than writing them from nothing. The window is a sheet: every translatable line of the map on
the left in English — the map name, the category names, and each marker's name, description and
photo captions — with its translation on the right, so a whole map is translated in one pass
instead of opening each marker in turn. Filter the lines, or tick **Untranslated only** to see just
what is left.

Editing a marker always writes the **English source**, whichever language you happen to be reading
in, so the two never get confused. Lines are keyed by the id of the thing they belong to, not by
position or by the text itself: renaming a marker or reordering its photos leaves its translations
attached to the right lines, and deleting a marker takes its translations with it.

### 5. Map properties

**Properties…** in the toolbar: the map's name, and its **identifier** — the GUID that says which
map this is wherever it has been copied to. It is what lets a download from GitHub land in the tab
that is already open instead of opening a second copy of the same map, so **Generate new** is the
deliberate way to fork a map into a separate one.

### 6. Several maps at once

Every open map gets a tab. Switching tabs preserves each map's own pan/zoom position, search text and
category toggles. Open tabs are restored the next time the app starts. `Ctrl+W` closes the current
map.

### 7. GitHub sync

**GitHub…** in the toolbar. Fill in owner, repository, branch, the folder maps live in, and a
personal access token with **Contents: read and write** on that repository.

Each map **remembers its own location** — owner, repository, branch and folder are stored on the map
itself as soon as they are entered, not only after a push succeeds. Open **GitHub…** on a map that
has been pushed before and everything is already filled in; the commit message defaults to
`Update <map name>`. Pointing a map at a different folder clears the sync bookkeeping for the old
one, since those shas describe a folder this map no longer has anything to do with.

* **Refresh** lists every map in the repository.
* **Download and open** pulls one into your local workspace and opens it in a tab.
* **Push** uploads the current map: `map.json` plus every image it actually references, as a
  **single commit** — collaborators see one atomic change per push, not a commit per file. Files
  whose content hasn't changed are not re-uploaded (the local git blob sha is compared against the
  remote tree), and files you deleted locally are deleted remotely.
* **Pull** replaces your local copy with the remote one and reloads the tab.

Before pushing, the tree sha of the map's folder is compared with the one recorded at your last
sync. If someone else pushed in the meantime you get a conflict warning instead of a silent
overwrite; **Overwrite remote changes** is the deliberate escape hatch.

The token is encrypted at rest with DPAPI under your Windows account — it is never written to disk
in the clear. Untick **Remember token** to keep it in memory for the session only.

## Where things are stored

```
%APPDATA%\DerpMap\
  settings.json          open tabs, recent maps, GitHub config, encrypted token
  Maps\
    <map-slug>\
      map.json           the map: categories, markers, translations, sync bookkeeping
      assets\            base image, custom icons, photos — named by content hash
```

A map folder is self-contained and portable: zip it, move it, or point the app at it from anywhere
with **Open…**. Assets are named by SHA-256 prefix, so attaching the same photo to five markers
costs one file.

Saving is automatic — two seconds after any change, and on close. `Ctrl+S` forces it.

## Project layout

```
src/DerpMap/
  Models/          serializable map format + app settings
  Services/        storage, asset import, image cache, icon library, GitHub Git Data API client,
                   AOT-safe JSON source-generation context
  ViewModels/      shell, map document (pan/zoom/search/language state), marker, category, photo,
                   translation
  Views/           map canvas, legend, marker card, marker editor, category manager, translation
                   sheet, map properties, GitHub sync
  Converters/      enum→geometry and hex→brush for the icon and colour pickers
```

The map canvas is a single transformed surface (`screen = world * zoom + offset`); markers are
positioned in base-image pixel coordinates and pivot on their own anchor, which is what makes the
counter-scaling exact at every zoom level.
